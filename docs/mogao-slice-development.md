# 莫高窟小切片：开发与试玩记录

日期：2026-09-20。状态：用户确认后已发布到生产，游戏版本 `10a234d`。以下保留开发与试玩阶段记录，最终发布验证见文末。

最新本地迭代：2026-09-22 的机关简化尚未推送或发布，见文末“第三轮”。上面的生产状态只对应 9 月 20 日版本。

## 本次实现

- 第二关改名莫高窟，补齐妈妈的前置线索、第二关入场、救援哥哥与进入三危山的剧情；第一、三关主体玩法不变。
- 保留 30×25 网格。在西北 11×10 区域内放置受控的路口、木匣、关门和暗廊绕行；其余区域继续采用现有随机生成。此阶段先保证切片可靠，不实现全图随机选择机关位置的扩展。
- 起点到路口六步；木匣位于 (4,2)，门位于 (4,2) 与 (5,2) 的连接边，哥哥位于 (14,4)。关闭时能绕行，打开后由木匣到哥哥实际少走 16 格。
- 一个机关、两枚纹扣。包含演示、四格观察、护帘遮挡、单格辨认、温和反馈和开门；失误不扣血，已扣合纹扣不回退。
- 可选手动落帘；连续两次失误可切到两枚纹样。没有分数、评级、统计或训练入口。
- 机关区域和救援点不刷怪、不刷道具，怪物不可追入；外部怪物和道具仍按原系统运行，敌人数量按可生成区域折算。
- 打开面板冻结玩家/怪物行为、冷却与道具消耗；保留现有五格背包与蓝色指引。满背包也能开门，机关不改变家人计数。
- 一次原始手势只执行一次机关动作；关闭面板等待按压释放，不把点击转换成行走/用药。滚轮不记为持续按住。
- 窗口变化或失焦中断正在观察的纹板，要求重新开始观察；失焦后的世界暂停不会被关闭面板意外解除。
- 新图案由引擎绘制，原人物图片和引擎锁未改。补充现有字体子集，不增加外部字体请求。

```sh

```

## 第二轮：让捷径被看见（2026-09-20）

用户试玩反馈：机关逻辑成立，但完成后没有明显感受到捷径。本轮不增加题目、评分或奖励道具，只补齐地图上的因果反馈。

- 把木匣、木门和蓝色围巾做成三件清晰的场景物件；木匣与门闩使用相同的菱形纹样，门不是一个“闭/通”文字徽标。
- 两路汇合点移到围巾 `(6,2)`；木匣到围巾，关闭时 18 步，开启后 2 步，仍然省 16 步。绕行经 `(8,8)`，不增加伤害或敌人。
- 完成后点“看看打开的通道”，回到真实地图，播放 1.6 秒门扇打开、三格栈道逐段亮起。声音本地合成，无新增音频下载。动画期间冻结战斗，不自动移动玩家。
- 开门展示只播放一次。离开浏览器时连动画一起暂停，桌面按 P/回车或手机点“点击继续”可恢复；结束动画的同一帧仍不推进战斗。
- 立刻启用现有蓝色箭头引玩家穿门，无需达到迷途步数阈值；跨过木匣→门的实际连接后交还原指引规则。走绕路抵达围巾也会结束这个临时引导。
- 路口使用真实地图的局部近景，同时展示门与围巾；发现围巾后恢复原地图视图。近景保留实际迷雾、位置与碰撞，不是额外插图。
- 小屏大字号时，仅在机关附近回收顶栏空白和日志条。保留方向键尺寸，满背包保留五个可选择槽位；独立为查看按钮留位，不压在门上。
- 演示按钮明确标注“不解锁”，演示结束提示“开始拨纹扣”。

验收新增：门在桌面/横屏/竖屏/小屏大字号下至少 48 CSS px，门与围巾同屏，查看按钮不遮挡门；门扇可见进度、展示期间冻结、立即引导、亲自穿门和两路汇合均进行浏览器实测。莫高窟五条流程、第一关五种规格回归、六项 Python 导出测试全部通过，浏览器无运行错误。Godot 最终 968 项断言通过、0 失败（仍有原有的退出资源清理警告）。已查看桌面、手机横竖屏与大字号的实拍截图；移动端为 Chrome 模拟触屏，并非真机认证。

## 下一次试玩看什么

1. 玩家能否一眼理解“解开是近路，不解也能走”？
2. 演示是否足够，还是文字仍偏多？
3. 两枚纹扣是否让人感到自己打开了木匣，而不是做题？

## 2026-11-06：方向一「转动栈桥」独立玩法原型

用户反馈第一、二关的探索循环重复，选择先试“改变道路”方向。此次不是在大迷宫里再插一个题目，而是用一处小箱庭验证新的核心动作：**看见蓝围巾 → 走到转柄旁 → 转动栈桥 → 亲自走过去**。

### 范围

- 只做一个短场景、一座可逆的栈桥，没有怪物、背包、计时、血量和记忆问答。暂不扩成三个洞窟，也不替换线上第二关。
- 蓝围巾从开始就可见；三兔纹样作为环境线索保留。本场景是虚构的复刻机关／壁画幻境，不表现移动真实文物。
- 横置时不通，转成纵向后才增加真实可走的格子；旋转只改道路，不移动玩家，不直接判定通关。只有走到围巾位置才完成。
- 两岸各有转柄，靠近才能转动；可再次转回。桥上禁止旋转，转动期间禁止走步，避免悬空或重叠输入。一按只走一格，不启用按住连走。
- 电脑用 WASD／方向键行走、空格或 E 转动；手机使用大方向键与场景转柄，也保留明确的“转动栈桥”按钮。
- 暂停／失焦冻结动作；重开仅重置这个原型，完全不读写正式进度。
- 二维程序几何绘制洞窟、桥面与围巾，复用现有主角 SVG 和三兔图。没有新引擎、新模型、大图或音频下载。

### 隔离与预览

原型和只读测试桥全部位于 `tests/bridge_slice/`、`tests/bridge_probe.*`。正式导出的 `tests/**` 排除规则不变；其他章节的测试导出也排除该原型目录。第一／二／三关运行脚本、正式字体、部署配置与引擎锁均不修改。

```sh

python3 tools/serve_web.py --port 8076 --dir artifacts/bridge-probe-export
URL=http://127.0.0.1:8076/ node tools/verify_bridge_slice.mjs
```

这是本机独立试玩地址，不是线上地址；不要发布 `bridge-probe-export`。浏览器需要可解析 Playwright 的 Node 环境。

原型专用字体只收录 `tests/bridge_slice/view.gd` 中的文字与常用标点、方向符号，不改正式字体。重建方式：

```sh
pyftsubset assets/fonts/NotoSansSC-Regular.ttf --output-file=tests/bridge_slice/font.ttf --text-file=tests/bridge_slice/view.gd --unicodes='U+0020-007E,U+2190-22FF,U+3000-303F' --layout-features='*' --notdef-glyph --notdef-outline --recommended-glyphs
```

### 这次试玩要判断什么

1. 不看长说明，能否发现围巾、理解“桥没接上”，并找到转柄？
2. 接通道路的反馈是否直观；玩家是否觉得“这是我接出来的路”？
3. 是否明显不同于第一关反复探路，而不是另一种弹窗答题？
4. 手机能否看清桥、围巾和角色，方向键／转柄是否容易点准？

本切片只有一个教学动作，不代表整关已有足够难度或重玩价值。确认手感后，再考虑“侧台中转”的第二窟；不在本次混入回廊找异常玩法。

## 2026-11-06：正式第二关「莫高窟」三机关本地候选

### 决策与范围

用户确认接路体验后要求完成第二关、增加洞窟感；开发中进一步明确“不能全是转桥”。因此取消侧台转桥与双桥方案，改为三个不同动作的连续小洞窟。第一关保留经典迷宫，第三关保留第一人称沙谷；只更新共用入口的章节分派，不修改这两关的规则、资产或场景。没有修改部署配置、引擎锁和家庭隧道，也没有推送／发布。

### 本轮内容

| 洞窟 | 玩家实际操作 | 世界反馈与目的 |
| --- | --- | --- |
| 入窟 · 转桥 | 靠近转柄，旋转一座桥，再亲自走过 | 找到哥哥蓝围巾；三兔纹样提示“共用”的观察角度 |
| 侧窟 · 压盘 | 身体试踩压盘，再绕到木箱侧面推动 | 身体离开门会落下，木箱留在盘上门才持续开启；亮线连接盘与门 |
| 深窟 · 灯影 | 提起灯笼，选择放到鹿纹／足迹灯座 | 鹿纹灯座照亮可选壁画；足迹灯座持续照亮真实可走的折线路径，找到哥哥后走到窟口 |

三个洞窟顺次衔接，一次只引入一个新操作。没有计时、生命惩罚、刷怪、记忆问答或大地图回头路。灯不会自动熄灭；未照亮的路有淡轮廓但不可乱闯；不会让整屏变黑。可选壁画不作为救援前置条件。

### 可恢复性与关卡契约

- 原生按钮与键盘均单次触发，不把触摸再解释成另一套移动；动画期间不排队，不在桥上转桥，不在暗廊上拿走支撑路线的灯。
- 支持逐步撤销：角色、木箱、桥向、灯的位置、线索状态一起恢复，不能只倒退角色导致谜题错位。换窟清空本窟撤销栈。
- 暂停冻结正在进行的动作；失焦自动暂停。重置需确认，只重置当前窟；返回首页另行确认，明确下一次从第二关入口开始。
- 取围巾不等于救出哥哥；见到哥哥有短对话，之后仍要走到右侧窟口。只有确认离开，正式控制器才进入第三关并保存其入口。
- 沿用原存档章节编号和难度／等级／经验字段：旧第二关存档进入新莫高窟入口，无格式迁移。没有将窟内局部进度伪装成已存档。
- 使用二维程序几何绘制窟壁、拱口、石阶、灯龛和机关；复用原角色 SVG、三兔与九色鹿示意图，不增加大图、音频或新引擎。
- 第二关使用独立小字体子集，不重建第一／三关字体；遵循已有浏览器系统字号缩放。第二关专属画布约束在退出章节时清理，避免把横竖屏修正扩散到其他关卡。
