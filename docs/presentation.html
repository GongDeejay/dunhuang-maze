🔍 游戏地图显示问题

一次调试之旅的经验教训

敦煌迷宫游戏 · Godot 4.7 · 2026-06-26

❓ 问题描述

在敦煌迷宫游戏中，地图最底部的2行格子始终不可见。

玩家无法看到完整的迷宫区域，影响游戏体验。

🎯 目标：让整个迷宫在任何分辨率下都能完整显示

📜 调试历程

尝试1: 修改相机Y轴钳制
尝试2: 修复缩放计算
尝试3: 添加底部边距
尝试4: 全局缩小10%
尝试5: 相对坐标自适应缩放 ✅

5次尝试，4次失败，最终找到根本原因

❌ 尝试1 & 2

尝试1: 修改GameCamera的Y轴钳制

在 game_camera.gd 中增加20px偏移量

结果：无效 — 问题不在相机钳制

尝试2: 修复非滚动模式的缩放计算

在 main.gd 中修复缩放因子计算，添加居中逻辑

结果：无效 — 根本原因是视口尺寸计算错误

❌ 尝试3 & 4

尝试3: 添加底部边距

为Godot编辑器底部工具栏预留40px空间

结果：无效 — 问题不在编辑器工具栏遮挡

尝试4: 全局缩放0.9

将整个地图缩小10%

结果：无效 — 缩小后底部行仍然被裁剪

✅ 尝试5: 相对坐标自适应缩放

最终方案

从窗口四角计算相对坐标，自动缩放确保完整显示

var scale_x = game_w / maze_pixel_w
var scale_y = game_h / maze_pixel_h
var draw_scale = min(scale_x, scale_y)
var offset = Vector2((game_w - scaled_w) / 2, 
                     (game_h - scaled_h) / 2)

结果：成功！整个迷宫完整显示

🔍 根本原因分析

1. 视口尺寸误解

get_viewport_rect().size 返回完整视口大小，但实际可用游戏区域更小

2. 坐标系混淆

使用绝对坐标而非相对坐标，导致边界计算错误

3. 过度复杂化

引入GameCamera滚动机制增加了复杂度，但没有解决核心问题

💡 关键教训

教训1: 优先使用相对坐标

# ❌ 错误：绝对坐标
var offset = Vector2.ZERO

# ✅ 正确：从窗口角落计算相对坐标
var offset = Vector2((game_w - scaled_w) / 2, 
                     (game_h - scaled_h) / 2)

教训2: 先计算可用区域再绘制

1. 计算可用宽度 → 2. 计算可用高度 → 3. 计算缩放 → 4. 计算居中偏移

💡 关键教训

教训3: 避免过早优化

  • 不要一开始就引入复杂机制（如Camera滚动）
  • 先用最简单的方法验证可行性
  • 只有在简单方法不够时才增加复杂度

教训4: 测试时关注边界情况

  • 始终测试地图的最大尺寸
  • 检查四角和边缘是否完整显示
  • 使用不同分辨率的窗口测试

🎯 最终方案优势

  • 简单 — 不需要Camera滚动机制
  • 可靠 — 从窗口角落计算，确保完整显示
  • 自适应 — 自动计算最佳缩放比例
  • 可维护 — 代码清晰，易于理解和修改

适用场景：

✓ 需要完整显示整个地图的游戏 · ✓ 地图尺寸可能变化的场景 · ✓ 需要自适应不同分辨率

🎓 总结
